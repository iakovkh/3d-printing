# 3D Printing Workflow Documentation Adoption Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Привести два действующих документа проекта в полное соответствие с утверждённым процессом создания и проверки 3D-моделей.

**Architecture:** `00_PROJECT_INSTRUCTIONS.md` остаётся коротким нормативным документом с обязательными правилами и стоп-условиями. `01_CLOUD_WORKFLOW.md` становится пошаговой операционной инструкцией для каждого проекта. Полная мотивация и архитектурные решения остаются в спецификации и не дублируются дословно.

**Tech Stack:** Markdown, PowerShell, ripgrep (`rg`)

**Spec:** `docs/superpowers/specs/2026-09-16-3d-printing-workflow-design.md`

## Global Constraints

- Принтер: Anycubic Kobra S1 Combo.
- Слайсер: Anycubic Slicer Next.
- Базовая конфигурация: PLA, сопло 0,4 мм, размеры в миллиметрах.
- Поддерживаются функциональные, органические, гибридные и многоцветные модели.
- Проверочные изображения создаются только после повторного открытия кандидатного 3MF и показываются прямо в чате.
- ID кандидата — первые восемь шестнадцатеричных символов SHA-256 файла `candidate.3mf`; полный SHA-256 сохраняется в QA и манифесте.
- После утверждения кандидатный 3MF не пересобирается; выпущенный файл должен побитово совпадать с кандидатом.
- Первая версия процесса заканчивается геометрическим 3MF; слайсинг выполняет пользователь.
- Git пока не используется. Файлы версионируются именами и неизменяемыми каталогами выпусков.
- Установка инструментов моделирования не входит в этот план и определяется первым реальным проектом.

### Task 1: Обновить нормативные инструкции проекта

**Files:**
- Modify: `00_PROJECT_INSTRUCTIONS.md`

**Interfaces:**
- Consumes: утверждённая спецификация процесса.
- Produces: краткий набор обязательных правил, используемый как политика для всех будущих моделей.

- [x] **Step 1: Сохранить назначение документа**

Оставить заголовок, дату, принтер, слайсер и единицы. Добавить базовую конфигурацию `PLA / 0,4 мм` и область применения: функциональные, органические, гибридные и многоцветные модели.

- [x] **Step 2: Заменить линейный процесс на утверждённые контрольные ворота**

Зафиксировать последовательность:

```text
INTAKE → WAITING_FOR_INPUT → READY_TO_MODEL → GEOMETRY_DRAFT
→ READY_FOR_REVIEW → APPROVED → RELEASED
```

Описать обязательное подтверждение ТЗ, опциональный концепт, создание кандидатного 3MF до утверждения, повторное открытие, QA, показ изображений в чате и перенос того же файла в выпуск.

- [x] **Step 3: Уточнить единый источник истины**

Для простой модели указать один канонический исходник. Для гибридной или многоцветной модели разрешить набор исходников, перечисленный в `source-manifest.json`. Запретить использование концепта как источника финального рендера.

- [x] **Step 4: Зафиксировать идентификацию и версионность**

Определить ID как первые восемь символов SHA-256 кандидатного 3MF. Запретить перезапись показанной версии и пересборку утверждённого кандидата. Сохранить формат `<название>_v001_<тип>.<расширение>` и назвать финальный файл `<name>_v001_geometry.3mf`.

- [x] **Step 5: Расширить QA и стоп-условия**

Добавить уровни `BLOCKER`, `WARNING`, `INFO`. Блокировать выпуск при ошибке повторного открытия, несовпадении хеша, единиц, размеров, состава частей, версии или при критическом дефекте геометрии. Указать, что предупреждения показываются до утверждения.

- [x] **Step 6: Проверить нормативный документ**

Run:

```powershell
rg -n "candidate|SHA-256|READY_FOR_REVIEW|RELEASED|BLOCKER|geometry\.3mf|source-manifest|прямо в чате" 00_PROJECT_INSTRUCTIONS.md
```

Expected: каждая обязательная тема присутствует хотя бы один раз; документ не утверждает, что 3MF впервые создаётся после одобрения.

### Task 2: Обновить операционный рабочий процесс

**Files:**
- Modify: `01_CLOUD_WORKFLOW.md`

**Interfaces:**
- Consumes: правила из обновлённого `00_PROJECT_INSTRUCTIONS.md` и утверждённая спецификация.
- Produces: пошаговая инструкция от голосового сообщения до передачи геометрического 3MF.

- [x] **Step 1: Добавить структуру папки проекта**

Внести каталоги `00_brief`, `01_concept`, `02_source`, `03_build/vNNN`, `04_review/vNNN`, `05_release/vNNN`. Указать, что выпуск неизменяем, а следующая правка создаёт новый номер версии.

- [x] **Step 2: Описать голосовой brief**

Добавить классификацию `FUNCTIONAL`, `ORGANIC`, `HYBRID` и карточку с назначением, габаритами, критичными размерами, материалом, соплом, цветами, обязательными признаками, допущениями, открытыми вопросами и критериями готовности. Разделить критичные вопросы и некритичные допущения.

- [x] **Step 3: Описать выбор ветки моделирования**

Зафиксировать SVG/OpenSCAD для плоских форм, CadQuery для точных деталей, Blender или разрешённый бесплатный/оплаченный облачный сервис для органики. Для органики сделать концепт обязательным; для точных моделей — только при неоднозначном внешнем виде.

- [x] **Step 4: Описать многоцветные и гибридные модели**

Требовать отдельные именованные тела для цветов, перечислять исходники и преобразования в `source-manifest.json`, запрещать органической обработке незаметно менять точные посадочные поверхности.

- [x] **Step 5: Описать кандидат, QA и рендеры в чате**

Добавить точную цепочку:

```text
исходники → экспорт → candidate.3mf → повторное открытие
→ QA → рендеры из reopened candidate.3mf → показ в чате
→ утверждение версии и ID → неизменённый выпуск
```

Перечислить обязательные изображения: front, back, side, top, isometric, dimensions, parts/colors. Указать опциональные разрезы, вид снизу, разобранную сборку и увеличенные посадки.

- [x] **Step 6: Описать утверждение, выпуск и передачу в слайсер**

Привести форму `Утверждаю <name> v003, ID 8F21C4A9`. Перечислить состав `05_release/vNNN`, подчеркнуть название `geometry.3mf` и ответственность пользователя за импорт, профиль, нарезку и отправку на принтер.

- [x] **Step 7: Добавить редкий тестовый образец и обратную связь**

Разрешить тестовый купон только для рискованных посадок или дорогой длительной печати. Добавить короткую форму обратной связи после печати и правило создания новой версии для исправлений.

- [x] **Step 8: Проверить операционный документ**

Run:

```powershell
rg -n "FUNCTIONAL|ORGANIC|HYBRID|candidate\.3mf|повторн|прямо в чате|SHA-256|05_release|Anycubic Slicer Next" 01_CLOUD_WORKFLOW.md
```

Expected: все термины находятся; процесс заканчивается самостоятельным слайсингом пользователя, а не автоматической отправкой на принтер.
